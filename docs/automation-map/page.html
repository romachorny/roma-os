One person, one server and a set of agents that run a small studio: sales in WhatsApp, job search on freelance and Israeli boards, mail, code and video. Everything on the map runs by itself. Five kinds of action wait for my word. Below: how to read the map, every line of it for engineers, and at the end what a client can order.

Five things wait for Roma

  • Money
  • Sending
  • Deletion
  • Access
  • Publishing

When a command in Telegram touches one of these, the bot holds it until Roma answers with a confirmation word. The word lives on the server and never appears in the chat, and a held command expires after 10 minutes. A keyword list outside the model makes this call, because a model can be talked round and a list cannot.

Everything else runs on its own: the scheduled agents, replies to WhatsApp clients, mail sorting and daily reports.

Who builds this, and how

I have no engineering degree. I design the flows and the rules, write the tests and review every change; Claude writes the code with me as a pair programmer. Years as a transport dispatcher taught me to think in queues and handoffs, and to plan for failure.

  • Tests before trustEvery build of the WhatsApp agent is checked against its own acceptance protocol: 17 scripted conversations, 9 blockers, every run graded against a reference generated from the code.
  • Reproduce, then fixEach reported bug is reproduced in a test first, and the fix is checked against the same test.
  • Hard limits outside the modelMoney, sending, deletion, access and publishing are gated by code, not by a prompt.
  • Everything in gitThe server config is exported to a private git repository every night, so every change can be traced and rolled back.

Every line on the map

Roma OS the control room in Telegram

  • Roma → Roma OS ↔ Claude

    Roma speaks or types into Telegram. The bot runs on a Hetzner server behind Cloudflare Tunnel, turns voice into text on the server, hands the task to Claude Code and sends the answer back.

  • Roma OS → scheduled agents

    systemd timers start Claude jobs with nobody at the keyboard: morning brief, mail watch and mail report, billing check, evening check, job boards scan.

  • Roma OS ↔ Roma approves

    Money, sending, deletion, access and publishing wait for the confirmation word. The rest goes through.

  • Vercel → Roma OS

    The Radar panel is hosted on Vercel and opens inside the Telegram bot.

WhatsApp sales agent live on the Meta Cloud API

  • WhatsApp ↔ Meta API ↔ agent

    Meta delivers each client message by webhook, and the agent answers back through Meta. The webhook reaches the server through Tailscale Funnel, where a small gate checks Meta's HMAC signature and masks card numbers before n8n sees anything.

  • agent → how it decides

    An n8n workflow of 37 nodes runs a rule engine. A language model only transcribes voice notes, so a prompt injection has nothing to take over.

  • agent → Airtable, Roma OS

    Saves the lead to Airtable and alerts Roma in Telegram along the top line.

  • agent → Agent Test Protocol

    Roma's acceptance test for the agent: 17 scripted conversations in four languages, each run five times, 9 of them blockers. Payment safety and prompt injection are blockers, following the OWASP Top 10 for LLM apps and PCI DSS.

Job search freelance and Israeli boards

  • Job boards ↔ Server Chrome

    Every two hours a scheduled agent reads XPlace, Behance and taasiya in the server browser, where Roma is logged in, and picks out the real paid jobs.

  • Upwork, Fiverr, LinkedIn → Gmail

    These sites are never opened from the server, so the accounts stay safe from datacenter logins. Their job alerts arrive by email, and the morning brief reads them through Gmail and puts the live ones in front of Roma.

  • Claude → Chrome → Server Chrome

    Claude drives the same browser over MCP. Jobs from every board, Israeli ones like Drushim and ShivukNet included, go to one Leads table in Airtable.

Site, code and video

  • genvidpro.com → Cloudflare

    The site is plain HTML on Cloudflare Pages, with the site assistant and the visit counter running at the edge.

  • Claude → GitHub

    Code for the site, the agents and the bots, drawn as the dashed line. A GitHub Action checks the site every 20 minutes.

  • AI Video ↔ Claude

    Flow and ElevenLabs make footage and voice for ads and films.

  • Claude → MCP links

    Short spokes to every service Claude reaches over MCP: Drive, Gmail, Calendar, Airtable, Exa, vidIQ, Cloudflare, Vercel, Chrome and Memory.

Server the shield in the legend

  • internet → server

    No inbound ports are open. Telegram comes in through Cloudflare Tunnel, the WhatsApp webhook through Tailscale Funnel, and SSH works only inside Tailscale.

Behind the map

  • BackupsEncrypted with GPG every night, copied to Google Drive and to Roma's PC.
  • Config in gitExported to a private GitHub repository every night, after a scan for secrets.
  • Boot checkAfter every restart the server checks itself, including that the WhatsApp webhook refuses a request without Meta's signature.
  • StagingA staging copy of the WhatsApp agent runs next to production.
  • PrivacyRaw webhook payloads are deleted every 10 minutes.
  • Voice on the serverSpeech recognition and speech synthesis run locally with whisper.cpp and piper.
